# NetLoom — памятка для Claude Code

NetLoom (НетЛум) — система мониторинга сети: .NET, WPF (`src/NetLoom.Wpf`), Desktop (`src/NetLoom.Desktop`), SQLite. Автор не читает код сам: объясняй по-русски, коротко и по делу, решения обосновывай правилами проекта, а не вкусом.

## Источники правды — читать перед работой

- `docs/AI_DEVELOPMENT_RULES.md` — как работать: сначала читать код, минимальные изменения, комментарии в коде на русском, формат отчёта, пакетный процесс.
- `docs/UI_DESIGN_RULES.md` — правила интерфейса; приёмка по §10 (доказательство, а не вкус; серьёзность ВЫСОКАЯ/СРЕДНЯЯ/НИЗКАЯ).
- `docs/DECISIONS.md` — ADR, особенно ADR-083 (оболочка Sprint 46) и поправка о профиле доступа.
- `docs/design/netloom-v2-*.png` — эталонные макеты ADR-083 (светлая и `-dark`).
- `docs/sprint46-mockup-gap.md` — акт сверки с макетами: каждое расхождение «открыто / исправлено / перенесено».
- `docs/PROJECT_STATE.md`, `docs/BACKLOG.md` — состояние и план спринтов.

## Как проверять интерфейс

- Одна команда: `powershell -ExecutionPolicy Bypass -File tools\Run-UiAudit.ps1` — сборка, тесты Sprint 46 и живой аудит.
- Итог: `artifacts\ui-audit-run\run.txt` (в конце `BUILD_EXIT` и `TEST_EXIT`).
- Аудит (`tests/NetLoom.Tests.Unit/Sprint46LiveUiAuditTests.cs`) открывает настоящее окно на копии `artifacts/realistic-stand/operator-s46-pass3-visual.db` (исходная база не меняется) и пишет в `artifacts\ui-audit\`:
  - `findings.txt` — нарушения (обрезка, контраст, имена UI Automation, площадь нажатия, сценарии кликов); строки «ИНФО» нарушениями не считаются;
  - `compare-<раздел>-<тема>.png` — макет слева, живой экран 1440×900 справа;
  - `<Раздел>-<ширина>-<тема>.png`, `interaction-*.png` — снимки разделов и сценариев.
- Экран принимается, когда аудит без нарушений и `compare-*` совпадает с макетом по строкам акта сверки. Смотри снимки сам, не проси пользователя пересказывать.
- `artifacts/` в git не попадает (исключён в `.git/info/exclude`).

## Правила правок

- Все размеры, отступы и цвета — токены (`Themes/DesignTokens.xaml`, `Light.xaml`, `Dark.xaml`); локальные числа в XAML — дефект ревью (§5).
- Контраст по §6: текст ≥ 4.5:1, крупный текст, значки и рамки ≥ 3:1; исправляется светлота, а не оттенок.
- Строки интерфейса — только в `Resources/UiStrings.ru.resx` и `Resources/UiStrings.resx` одновременно; проверять, что ключ не дублируется.
- Новые постоянные элементы в верхнюю строку не добавлять (запрет из `AI_DEVELOPMENT_RULES.md`).
- Сохранять кодировку и переводы строк файла (рабочая копия Windows: CRLF, у большинства файлов BOM).
- Существующие тесты описывают принятые решения; если тест падает после правки — сначала понять, что он защищает, и только потом менять код или тест.
- Коммитить и пушить только по явной просьбе пользователя; сообщение коммита — на английском, как в истории.
