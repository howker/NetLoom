# NetLoom — функции для демонстрации и продаж

Статус документа: **candidate strategy, не обязательство.** Порядок включения
в `Committed sequence` определяется после Sprint 45 (прогон на реальной сети)
по `FRICTION_LOG.md`. Текущая committed sequence 43 → 44 → 45 → 46 этим
документом не меняется.

Редакция 2: учтены тринадцать поправок ChatGPT. Все прежние завышения
исправлены — формулировки приведены к тому, что NetLoom реально умеет.

**Главный принцип демонстрации:** показывать только то, что система делает
на самом деле. Для продукта, чьё отличие — честность, завышенное демо
разрушает основу позиционирования.

# Группа A. Уже работает — нужен сценарий показа

## A1. Карта собирается на глазах

Обнаружение по диапазону — узлы появляются по мере нахождения.

**Есть:** потоковое обнаружение (Sprint 42), инкрементальная сверка
(Sprint 33A), анимация появления (Sprint 36).

## A2. Почему система уверена в связи

Клик по связи — основание: LLDP, CDP или корреляция ARP/FDB, источник,
время, достоверность.

**Есть:** панель диагностики (Sprint 35), evidence (Migration010).

## A3. Система говорит «не знаю»

Показать связь, в которой система не уверена: «вывод по корреляции FDB,
прямого подтверждения LLDP нет».

**Есть:** модель достоверности, визуальный язык связей (Sprint 39).

## A4. Изменение состояния кольца — детерминированный сценарий

**Нельзя** показывать через остановку агента snmpsim: по архитектурному
инварианту один таймаут не удаляет устройство и связь. Остановленный агент
даст Aging, затем Stale, а не мгновенный переход — демо «не сработает»
именно потому, что продукт ведёт себя правильно.

**Правильно:** для коммутатора кольца готовятся две версии `.snmprec` —
«до» и «после». В версии «после» меняется **только состояние STP** —
например порт в `dot1dStpPortState` переходит из `forwarding` в `blocking`
или `disabled`. Подмена файла и перезапуск агента — следующий опрос
детерминированно получает изменённое STP-наблюдение, которое
`RingProtectionAnalyzer` потребляет в этом же цикле.

**Не использовать отсутствие связи в LLDP:** пропадание LLDP в одном опросе
по правилам свежести даёт Aging, а не исчезновение связи — сценарий снова
станет недетерминированным.

**Перед тем как считать сценарий готовым** — один раз автоматизированно
доказать всю цепочку:

```
.snmprec → observation → materialization → analyzer → alert transition
```

После этого сценарий демо одновременно является регрессионным тестом.

**Есть:** `RingProtectionAnalyzer` (Sprint 29), предупреждения (Sprint 31).

## A5. Поиск устройства за две секунды

«Где камера 47?» — ввести MAC, получить коммутатор и точный интерфейс
**в панели деталей**; карта фокусируется на устройстве.

Подсветки конкретного порта на карте сейчас нет — она остаётся отдельным
кандидатом.

**Есть:** поиск MAC/IP (Sprint 30), фокус на устройстве (Sprint 36).

## A6. Работает без интернета

Отключить **WAN / внешний маршрут**, сохранив локальную сеть. Не выдёргивать
единственный Ethernet ноутбука — иначе отрежется и сама локальная сеть, и
демонстрация покажет обратное.

**Есть:** локальный Engine, локальный SQLite.

# Группа B. Презентация существующего анализа

## B1. Экран «Состояние сети»

**Результат для оператора:** сразу после обнаружения увидеть структурные
риски собственной сети, о которых он не знал.

Экран делится на три группы — это ложится на философию NetLoom:

```
СТРУКТУРНЫЕ РИСКИ — доступны сразу после обнаружения
  3 связи, при недоступности которых часть известной топологии
    оказывается отделённой
  Кольцо «Корпус Б»: резерв не подтверждён

АКТИВНЫЕ ПОДТВЕРЖДЁННЫЕ ПРОБЛЕМЫ — появляются со временем
  2 порта с растущими ошибками

НЕДОСТАТОЧНО ДАННЫХ
  Деградация интерфейсов: нужен базовый замер и следующий интервал
  14 устройств без SNMP-ответа
```

**Реализовано и может входить:**
`PhysicalGraphSafetyAnalyzer` (мосты графа, `PhysicalLinkFailureImpact`),
`RingProtectionAnalyzer`, анализ циклов пересылки, деградация интерфейсов.

**Не реализовано и в первую версию не входит:** «вероятно неучтённый
коммутатор по нескольким MAC за портом» — отдельный кандидат бэклога.

**Про время:** деградации нужен валидный предыдущий замер счётчиков,
следующий интервал и настроенные пороги. Через пять минут после обнаружения
доступны только **структурные** риски. Формулировка демо: «через пять минут —
структурные риски вашей сети».

## B2. Режим «что будет при недоступности связи»

Навести на связь — подсвечиваются устройства, которые окажутся **в
отделённой части известной физической топологии** при её недоступности.

**Нельзя** формулировать как «вот что отвалится»:
`PhysicalLinkFailureImpact` описывает структурное разделение известного
графа, а не гарантированную недоступность сервиса или адреса. Более сильное
заключение допустимо только при подтверждённом резерве и forwarding evidence.

**Есть:** расчёт влияния (Sprint 35). **Нет:** режима подсветки на карте.

## B3. Журнал изменений топологии

**Результат для оператора:** видеть, что и когда изменилось, и посмотреть
карту на момент до изменения.

Реализация раздела 51 ТЗ (`Network Event`), который описан и не реализован.

**Архитектура — не «журнал без снимков».** Формула «карта в T = текущая минус
изменения после T» недостаточна: она работает, только если каждое событие
обратимо. Удалённое устройство, смена имени или Location, уточнение
endpoint'ов, ручная правка — без данных «до» назад не восстановить.

Практичная схема:

```
событие изменения   полная обратимая полезная нагрузка «до» и «после»
контрольная точка   редкая, ограничивает длину обратного прохода
```

Гораздо дешевле постоянных полных снимков. К временным рядам метрик не
относится, P0 про ряды не затрагивает.

**Принцип:** изменение и событие «до/после» записываются атомарно, в одной
транзакции `BEGIN IMMEDIATE` (Sprint 26A).

**Точки захвата — не два метода, а все пути изменения.** Предварительный
перечень по коду:

```
SqliteMaterializedTopologyRepository   SaveDevice, SaveInterface,
                                       SavePhysicalLink,
                                       ReplacePhysicalLinkEvidence,
                                       DeleteManual* (динамический DELETE)
SqliteLocationRepository               сохранение, удаление
SqliteMapLayoutStore                   раскладка устройств и вида
SqliteObservationDeviceBindingStore    привязка наблюдений
```

Если хоть один путь обходит запись события, историческая карта ненадёжна.
Перед реализацией — аудит, доказывающий полноту.

**Решить до аудита — что входит в историческую карту:**

- устройства, интерфейсы, связи, удаления, Locations — да;
- раскладка — показывать узлы там, где стояли тогда, или там, где стоят
  сейчас? Второе проще и, вероятно, полезнее: оператор узнаёт свою карту;
- evidence — нужно для «почему связь считалась существующей в момент T»,
  но не для самой карты.

Ответ на два последних вопроса сокращает аудит примерно вдвое.

# Группа C. Документы для объекта

## C1. Экспорт схемы

**Committed как Sprint 44: PNG + CSV.** Остальное — только после аудита.

**PNG** — растр по ограниченному экспортному визуалу по границам фактической
топологии: объединение устройств из `map_device_layout` и рамок Locations,
плюс поля. Не по живому `Canvas` — он миллион на миллион логических единиц.

**CSV** — из того же согласованного read-set, UTF-8 с BOM.

Решить заранее: экспорт отдаёт всю топологию объекта, игнорируя временные
фильтры и фокус, разворачивая свёрнутые Locations.

**SVG и draw.io — stretch goal Sprint 44, только если аудит покажет малую
границу.** «Та же сериализация, почти бесплатно» не доказано: `MapSnapshot`
может не содержать всего для точного воспроизведения операторской раскладки,
рамок Locations, размещения подписей и визуальной грамматики.

**Путь draw.io → Visio проверить на реальном `.vsdx` в целевой версии
Visio** до обещания заказчику. Не обещать полноценную редактируемость
соединителей только потому, что формат импортируется.

## C2. Предпросмотр работ на L2-модели сети

Название — **«предпросмотр работ»** или **«наблюдаемая L2-модель сети»**, не
«цифровой двойник»: термин создаёт у заказчика ожидание значительно более
полной модели.

**Результат для оператора:** перед выездом увидеть, как запланированные шаги
работ влияют на связность известной топологии, и взять на объект документ.

### Первая версия — без предсказания STP

Последовательное структурное влияние на копии известного графа:

```
Шаг 1  Отключить SW-B4 Gi1/0/2    известная топология остаётся связной
Шаг 2  Переставить кабель МК-1     остаётся связной
Шаг 3  Отключить SW-B5             резерв кольца не подтверждён
Шаг 4  Заменить SW-B1              14 устройств в отделённой части
```

Реализация — поверх `PhysicalGraphSafetyAnalyzer`, накопительно по шагам.

### Предсказание STP — отдельно и позже

Два OID (`dot1dStpPriority`, `dot1dBaseBridgeAddress`) закрывают только
идентичность собственного моста для CIST. Основная работа — корректный
пересчёт выборов корня, корневых и назначенных портов **со всеми правилами
разрешения ничьих**, параллельными связями и неполным evidence.

Если делать — очень консервативным подмножеством CIST и только после
подтверждения на реальном стенде. RSTP, MSTP, PVST и вендорские кольца
остаются `CannotPredict`.

### Критерий «резерв сохраняется» — необходимые условия

Одного «весь путь Confirmed» **недостаточно**. Вердикт допустим, только
если одновременно:

- все связи резервного пути в состоянии Confirmed;
- все они свежие;
- полная привязка endpoint'ов;
- нет неразрешённого покрытия;
- ровно один поддерживаемый экземпляр протокола защиты / STP;
- Все участвующие устройства покрыты наблюдением.

Подтверждённая физическая связь не означает, что система знает поведение
протокола резервирования. Иначе — «не подтверждено» с перечнем причин.

**Перед реализацией условия должны стать машинными предикатами**, чтобы
Confirmed / Not confirmed / Cannot predict было детерминированным
контрактом с тестами:

```
свежие              PhysicalLinkFreshness == Fresh
                    (уже определено в NetLoom.Domain/Topology/TopologyEnums.cs)

Покрыты наблюдением  устройство покрыто, если одновременно:
                     — есть привязка в observation_device_bindings;
                     — последний успешный опрос в пределах окна свежести;
                     — устройство входит в набор целей мониторинга
                       (появится с Sprint 43)
```

Третье условие покрытия зависит от мультицелевого мониторинга — ещё одна
причина, по которой C2 стоит после Sprint 43.

### Проверка после работ

После работ — повторный опрос и сравнение предсказанного конечного
состояния с фактическим. Ловит разомкнутое после ремонта кольцо.

### Трассируемость подписываемого документа

PDF для подписи обязан содержать:

- время снимка evidence, на котором построен вывод;
- версию NetLoom;
- идентификатор или хэш исходного состояния;
- Явный список непокрытых и неподтверждённых элементов.

Иначе через месяц невозможно доказать, на основании какого состояния был
сделан вывод.

### Жёсткие границы

- только чтение: NetLoom ничего не переключает;
- время сходимости не обещается никогда;
- L3-моделирование путей (маршруты, ACL, NAT) в продукт не входит;
- Новое называть не «симулятор» — в `tools/` уже есть `NetLoom.Simulator`.

# Демо-стенд — отдельный артефакт

Воспроизводимая топология в snmpsim с заложенными проблемами:

- кольцо с двумя версиями `.snmprec` для детерминированной смены STP (A4);
- связь, отделяющая часть топологии (B1, B2);
- порт с ростом ошибок — при заранее подготовленном базовом замере (B1);
- Связь с неполной достоверностью (A3).

Один скрипт — стенд поднимается одинаково. Одновременно инструмент продаж
и приёмочный регрессионный тест.

## Порядок показа

```
1. Обнаружение                 → карта на глазах                      A1
2. «Состояние сети»            → структурные риски за пять минут      B1
3. Клик по связи               → почему система уверена               A2
4. Клик по неуверенной связи   → «здесь не знаем»                     A3
5. Навести на связь            → отделённая часть топологии           B2
6. Подмена .snmprec в кольце   → резерв не подтверждён                A4
7. Журнал изменений            → что и когда изменилось               B3
8. Поиск по MAC                → коммутатор и интерфейс в деталях     A5
9. Отключить WAN               → всё работает                         A6
10. Экспорт                    → схема и перечень оборудования        C1
```
