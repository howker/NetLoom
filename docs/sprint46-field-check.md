# Sprint 46 — автоматическая полевая проверка («как инженер на объекте»)

Дата: 2026-10-07. Основание: `docs/UI_DESIGN_RULES.md` §10 (приёмка — доказательство, а не вкус), `CLAUDE.md` («для закрытия Sprint 46 нужны полевые проверки: restart, export, поиск MAC/IP»). Настоящий объект пока недоступен, поэтому проверка выполнена на полевом стенде — синтетической сети, собранной по образцу объекта Sprint 45.

Статус: **исправлено** — подтверждено тестом; **перенесено** — пробел (программа этого не умеет), спринт выбран владельцем.

## Стенд

`FieldStandBuilder` (тест категории `StandBuilder`) строит сеть и прогоняет через неё настоящий конвейер: обнаружение семь дней назад, затем два цикла опроса (LLDP, CDP, FDB, ARP, состояние, порты, STP) через `MonitoringRuntime` и SQLite. Ответы SNMP даёт имитатор `SimSnmpTransport` — таблицы те же, что у настоящих коммутаторов. Адреса — только документационные (198.51.100.0/24), MAC — локально администрируемые (02:4E:4C:…).

- Размещения: «Площадка А» › ПС-1 (Серверная, Щитовая), ПС-2 (Аппаратная), «Корпус Б» (Узел связи).
- Ядро: два коммутатора с оптическими портами, соединённые двумя кабелями (на одном STP блокирует порт), маршрутизатор с таблицей ARP.
- Кольцо ПС-1 из 8 коммутаторов на паре ядра, один порт штатно заблокирован STP.
- Кольцо ПС-2 из 8 коммутаторов на одном ядре; участок ps2-sw-03 ↔ ps2-sw-04 оборван, заблокированный порт перешёл в пересылку — кольцо без резерва.
- «Корпус Б»: 6 коммутаторов; у kb-sw-04 выключен LLDP (сосед видит его, он соседа — нет), kb-sw-06 недоступен три дня.
- 3 сервера, 6 ИБП, 6 ручных устройств (медиаконверторы и пр.) и 7 ручных связей. В корпусе Б kb-sw-02, неуправляемый коммутатор поста охраны и МК-3 образуют кольцо без данных STP у двух ручных участников.
- 64 оконечных устройства (камеры, ПЛК): MAC в FDB коммутаторов доступа, IP в ARP маршрутизатора.
- Итог: 40 устройств на карте (34 опрашиваемых и 6 ручных), 317 портов. Число связей и оснований после изменения кольца корпуса Б требует повторного прогона стенда.

## Метод

`Sprint46FieldCheckTests` (категория `FieldCheck`) открывает настоящее окно на копии базы стенда и делает то, что делает инженер: открывает разделы, фильтрует, выбирает устройства, ищет, меняет настройки, проверяет ввод, экспортирует, перезапускает. Ожидания берутся из модели сети стенда, а не задаются числами. Отчёт — `artifacts/field-check/field-check-report.txt` и снимки `F*.png`.

```
dotnet test tests/NetLoom.Tests.Unit/NetLoom.Tests.Unit.csproj --filter "TestCategory=StandBuilder"
dotnet test tests/NetLoom.Tests.Unit/NetLoom.Tests.Unit.csproj --filter "TestCategory=FieldCheck"
```

| Сценарий | Что проверяется |
|---|---|
| F01 | Запуск: на карте все устройства объекта |
| F02 | «Оборудование»: таблица, фильтры «Ручные», «С проблемами», «Нет данных» |
| F03 | Фильтр таблицы по имени, IP, модели |

## Найденные ошибки

| № | Что увидел инженер | Причина | Серьёзность | Статус |
|---|---|---|---|---|
| P1 | Поиск по IP камеры ничего не находит, хотя маршрутизатор знает адрес | `ArpCollector` переходил на старую таблицу ipNetToMediaTable только при ошибке протокола. Устройство без ipNetToPhysicalTable отвечает на обход пустым списком — ARP оставался пустым | ВЫСОКАЯ | исправлено (переход и при пустом ответе; тест `EmptyModernTableFallsBackToLegacyTable`, F08 «IP камеры») |
| P2 | Результат поиска — «Устройство и интерфейс разрешены точно · 02:4E:… · ifIndex 3»: ни коммутатора, ни имени порта, ни IP | Строка собиралась из внутреннего состояния и номера ifIndex | ВЫСОКАЯ | исправлено (макет netloom-v2-7: «IP · MAC · за портом ps1-sw-01 · Port 2 · Только что»; если порт неизвестен — «на <коммутатор>, порт не определён»; F08) |
| P3 | Часть MAC «00:90:e8:38» из макета netloom-v2-7 не ищется | Поиск принимал только полный MAC | СРЕДНЯЯ | исправлено (4–11 шестнадцатеричных знаков с разделителем — поиск по началу адреса в FDB и ARP; без разделителя — нет, чтобы не путать с именем устройства; тесты `FieldCheckLookupTests`, F08) |
| P4 | В «Модель или описание» и в поле «Описание» инспектора — MAC шасси вместо модели | Проекция карты подставляла LLDP chassis ID, когда модели нет | СРЕДНЯЯ | исправлено (ADR-083: модель или «—»; MAC шасси остаётся в «Технических деталях»; F04) |
| P5 | Два быстрых «+» — карта пустеет, и пустой вид сохраняется в базу (после перезапуска тоже пусто) | Второе нажатие брало центр из прокрутки, которую первое ещё не выполнило (она отложена до Loaded) | ВЫСОКАЯ | исправлено (ожидаемый центр запоминается до прокрутки; тест `RapidZoomClicksKeepViewportCenter` в Run-UiAudit — без исправления падает; F14) |
| P6 | Все ручные устройства в счётчике «Нет данных», у них «Нет данных» в адресе и описании | Отсутствие опроса считалось отсутствием данных | СРЕДНЯЯ | исправлено (ручные не попадают в «Нет данных» — для них фильтр «Ручные»; адрес и «Обновлено» — «—», описание — «Ручное», как в макете netloom-v2-2; F02, F06) |

## Не проверено

- Настоящий опрос и обнаружение через Engine (стенд вызывает тот же конвейер напрямую, имитатором SNMP).
- Системные диалоги сохранения файла при экспорте (экспорт проверен вызовом той же службы).
- Windows Server 2012 R2, Windows 8.1, медленный RDP, настоящие 55 устройств с оптикой и SFP.
