# ЧАСТЬ I. ФИЗИЧЕСКАЯ СХЕМА SQLITE

# 1. Общие правила хранения

## 1.1. GUID

Все постоянные идентификаторы сущностей хранятся как:

```text
TEXT
```

в формате GUID:

```text
xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

Использование `TEXT`, а не бинарного GUID, выбрано осознанно:

- БД можно анализировать вручную;
- проще диагностика через SQLite Browser;
- проще работа с ИИ;
- проще JSON export/import;
- при целевом размере до нескольких сотен устройств потеря производительности несущественна.

---

# 2. Время

Все timestamps в БД хранятся в UTC.

Формат:

```text
2026-09-01T17:30:45.123Z
```

Тип SQLite:

```text
TEXT
```

UI преобразует UTC во время локальной Windows-системы.

Нельзя хранить часть времени в local time, а часть в UTC.

---

# 3. Boolean

Boolean хранится:

```text
INTEGER
```

где:

```text
0 = false
1 = true
```

---

# 4. Enum

Enum рекомендуется хранить текстом.

Например:

```text
Confirmed
Observed
Inferred
Manual
```

а не:

```text
1
2
3
4
```

Это облегчает:

- ручную диагностику БД;
- миграции;
- работу с JSON;
- работу разработчика и ИИ.

Жёсткие CHECK constraints на enum на ранних стадиях не использовать, чтобы добавление новых состояний не требовало перестройки таблиц SQLite.

---

# 5. Миграции

Создать таблицу:

```sql
CREATE TABLE schema_migrations (
    version         INTEGER PRIMARY KEY,
    name            TEXT NOT NULL,
    applied_at_utc  TEXT NOT NULL
);
```

Миграции:

```text
001_initial.sql
002_locations.sql
003_observations.sql
004_topology.sql
...
```

Приложение при запуске Service должно:

1. прочитать текущую SchemaVersion;
2. определить отсутствующие migration;
3. выполнить их последовательно в транзакции;
4. записать результат.

Silent изменение схемы запрещено.

# 64. CycleDetector

Алгоритм работает только с физическим графом.

В граф входят:

- автоматически подтверждённые линии;
- Observed;
- Inferred — по настройке анализа;
- Manual.

Для основного режима рекомендуется:

```text
Confirmed + Observed + Manual
```

Для диагностического:

```text
+ Inferred
```

# ЧАСТЬ V. КЛЮЧЕВЫЕ ARCHITECTURE DECISIONS

Зафиксировать сразу в `DECISIONS.md`.

```text
ADR-001
DeviceId является GUID. IP не является идентичностью устройства.

ADR-002
Observation отделён от PhysicalLink.

ADR-003
FDB означает MAC reachability, а не физическое подключение.

ADR-004
bridge-port всегда сопоставляется через dot1dBasePortIfIndex.

ADR-005
Link Strength и Freshness являются независимыми свойствами.

ADR-006
Временная недоступность не удаляет Device или Link.

ADR-007
Ручные устройства являются частью общего физического графа.

ADR-008
Ручные устройства участвуют в поиске колец.

ADR-009
Мониторинг может быть полностью остановлен оператором.

ADR-010
Health, Interface Monitoring и Topology Discovery имеют независимое расписание.

ADR-011
ICMP не является критерием существования Device.

ADR-012
Credentials задаются только оператором. Credential guessing запрещён.

ADR-013
WPF является представлением, а не владельцем domain state.

ADR-014
После выделения Service UI не пишет SQLite напрямую.

ADR-015
Автоматический Discovery не перемещает зафиксированные пользователем элементы карты.

ADR-016
Location является отдельной сущностью и не кодируется в имени Device.

ADR-017
Vendor-specific особенности изолируются в VendorAdapter.

ADR-018
Turbo Ring не интерпретируется как RSTP.

ADR-019
STP state хранится как Observation с InstanceId.

ADR-020
Причинно-следственная связь аварии не объявляется автоматически; Event Correlation формирует только вероятную корреляцию.
```

# Дополнение: cross-platform архитектура

Этот раздел имеет приоритет над более ранними Windows-only схемами Приложения в части runtime, Service/Engine и IPC.

```text
NetLoom.Domain                 netstandard2.0
NetLoom.Application            netstandard2.0
NetLoom.Contracts              netstandard2.0
NetLoom.Topology               netstandard2.0
NetLoom.Protocols.Snmp         net48;net8.0
NetLoom.Persistence.Sqlite     net48;net8.0
NetLoom.Service                net48 — legacy Windows host
NetLoom.Wpf                    net48 — Windows client
NetLoom.Engine                 net8.0 сейчас — modern Windows/Linux host
```

Правила:
- portable core не содержит Windows-only API;
- Service и Engine используют одинаковые Domain/Application contracts;
- Named Pipes — только Windows transport implementation;
- сетевой transport для Linux/remote deployment выбирается отдельным ADR;
- после service split WPF не пишет SQLite напрямую;
- DPAPI исключается из modern target, Linux secret protector реализуется отдельно;
- production modern runtime переводится на .NET 10 LTS после обновления SDK/toolchain;
- основной backend не переписывается на Go; возможен отдельный будущий distributed `NetLoom.Probe`.

## ополнение: Topology Resolver v1

онвейер построения физической топологии:

`Observation → normalized evidence → correlation → PhysicalLinkCandidate → lifecycle/materialization → PhysicalLink`

`PhysicalLinkCandidate` не является подтверждённым физическим линком.

ля каждого candidate должны быть доступны:
- claims локального и удалённого endpoint;
- protocol-specific port references;
- confidence;
- evidence strength;
- источник evidence;
- observation_id и capturedUtc, если evidence происходит из Observation;
- объяснение причины формирования candidate.

равила безопасности resolver:
- FDB-only не создаёт PhysicalLinkCandidate;
- ARP/FDB-only не создаёт PhysicalLinkCandidate;
- weak evidence может только усиливать уже существующий strong adjacency candidate;
- IP не используется как DeviceId;
- bridgePortIndex не считается ifIndex;
- LLDP localPortNumber не считается ifIndex;
- CDP cdpCacheIfIndex не считается ifIndex;
- неоднозначное port mapping не разрешается угадыванием.
## ополнение: lifecycle и stale

Lifecycle физической топологии должен быть независим от результата отдельного poll.

одель freshness:
- `Fresh` — evidence актуален;
- `Aging` — evidence стареет;
- `Stale` — evidence давно не подтверждался.

нварианты:
- `poll failure != deleted`;
- `timeout != device absence`;
- `missing evidence != physical link deletion`;
- `stale != deleted`;
- manual topology защищена от автоматического удаления discovery;
- повторно появившееся evidence обновляет LastSeenUtc и возвращает discovered topology в Fresh;
- более старое evidence не уменьшает LastSeenUtc.

о materialization стабильных DeviceId/PhysicalLinkId отдельное lifecycle persistence по временным строковым ключам не создаётся.
## ополнение: Map v1

рхитектура отображения:

`Topology → TopologyMapProjector → NetLoom.Contracts.MapSnapshot → NetLoom.Wpf`

MapSnapshot содержит:
- MapNode;
- MapLink;
- confidence;
- freshness;
- evidence;
- generatedUtc.

нварианты:
- WPF не принимает решения о PhysicalLink;
- MapNode.Key является только presentation key;
- presentation key не является DeviceId;
- IP не становится DeviceId;
- duplicate reverse links объединяются;
- self-link не отображается;
- одинаковый вход должен давать deterministic layout;
- topology business logic остаётся вне UI.

NetLoom.Wpf не должен зависеть от NetLoom.Topology для topology resolution.
