# Задание: Sprint 49 — читаемая карта большого объекта

Заполнено 2026-10-08. Архитектор работает по этому файлу, `docs/autopilot/ROLES.md` и `CLAUDE.md`.

Источники требований: `docs/BACKLOG.md` (Sprint 49), `docs/sprint46-ui-ux-redesign.md` (раздел «Sprint 49»), акт сверки `docs/sprint46-mockup-gap.md` (строки M2, M3, остаток A4, K4), ADR-079 и ADR-083 в `docs/DECISIONS.md`, `docs/UI_DESIGN_RULES.md`, макеты `docs/design/netloom-v2-1-karta*.png` и `netloom-v2-3-pravka-na-karte*.png`.

Итог для оператора: на 55 и более устройствах карта читается без массовых наложений, оператор понимает, что сейчас в фокусе, и видит, где данные неполны и где ручная схема расходится с наблюдаемой. Главный принцип — показывать меньше, а не строить универсальный движок раскладки.

## Ветка

`sprint49/readable-map` от `main`. Каждый пункт — отдельный коммит (или несколько), после каждого принятого пункта ветка отправляется на сервер.

## Пункты — строго по порядку

1. Параллельные связи. Несколько физических связей между одной парой устройств показываются раздельно, а не одной линией. Модель `LinkKey` их уже различает — сначала проверить текущую отрисовку и исправлять только слой отображения.
2. Фокус на связи. Наведение на связь подсвечивает ровно два её порта, остальные связи приглушаются; то же самое — при выборе связи, чтобы не зависеть от мыши.
3. Строка качества данных над картой: «Топология неполная: N» с раскрытием причин (связи уровня Observed, синтетические интерфейсы, односторонний LLDP из Sprint 48 и другие пробелы, которые уже есть в модели). Полную топологию строка не показывает. Новых постоянных элементов в верхней строке окна не добавлять — строка относится к карте.
4. Расхождения ручной и наблюдаемой топологии (ADR-079): видны на карте и в инспекторе, у каждого — явные действия оператора, которые предписывает ADR-079.
5. Размещения (M2). Рамка размещения — одна рамка с подписью-вкладкой, как на макете `netloom-v2-1-karta`; кнопка сворачивания — нейтральная, не синяя. Ручные позиции и сохранённая ручная геометрия неприкосновенны; автоматическое разведение без наложений — только для новых узлов и размещений, появившихся после обнаружения. Если сохранённые ручные рамки накладываются друг на друга, это показывается оператору понятно (например, в строке качества), а не исправляется молча.
6. Семантический масштаб — четыре уровня: издалека (размещения), средний (устройства), вблизи (порты и подписи связей), подробно. Что показывается на каждом уровне, решить по правилам и записать в `BACKLOG.md`.
7. Фокус-окрестность: выбранный узел и его непосредственные соседи, явные действия «Раскрыть вверх», «Раскрыть вниз», «Вся площадка». Полезный стартовый вид большого объекта (M3) и вписывание участников предупреждения без мелких подписей (остаток A4) решаются через этот вид и семантический масштаб, а не через уменьшение ниже `NetLoom.Map.ReadableZoomMin`. Что такое «вверх» (ближе к точке опроса Engine) — решить по `ARCHITECTURE.md` и записать.
8. Навигация: `F` — фокус на выбранном; `Esc` — назад к карте в прежнем масштабе; `Alt+←` — предыдущий вид; удержание пробела — временное панорамирование; двойной щелчок по размещению вписывает его поддерево; `Shift+щелчок` по двум устройствам показывает кратчайший известный физический путь между ними. Не ломать существующие сочетания клавиш оболочки (Ctrl+K и другие).
9. Клавиатура на карте (K4, §8): узлы, связи и кнопки сворачивания размещений получают фокус с общим кольцом фокуса, Enter выбирает, стрелки переходят к соседям, у изменения раскладки есть путь с клавиатуры.

Если останется время: история выбора (вперёд/назад) — необязательный пункт BACKLOG; без него спринт считается выполненным.

## Как работать

- Проверять на большом стенде: полевой стенд `FieldStandBuilder` (`--filter "TestCategory=StandBuilder"` → `artifacts/realistic-stand/field-s46.db`, около 55 устройств) и стенд аудита `operator-s46-pass3-visual.db`. Исходные базы не менять — работать на копиях, как живой аудит.
- Макета для новых элементов (строка качества, действия фокус-окрестности, расхождения) нет: решать по `UI_DESIGN_RULES.md`, ADR-083 и существующим элементам панели инструментов карты, токенами.
- Неоднозначное требование — самое узкое толкование, совместимое с ADR; решение записать в `BACKLOG.md` («Implementation decisions») и вынести в отчёт на подтверждение владельцу. Работу не останавливать.
- Миграции, Application и Domain менять можно, только если пункт этого требует (например, сохранение вида); миграция только добавляет.
- Пункт, который не получается после двух попыток, отложить с причиной и идти дальше; зависящий от него — тоже отложить.
- После каждого принятого пункта обновлять `docs/autopilot/REPORT.md` (начать новый отчёт для Sprint 49), запись реализации Sprint 49 в `BACKLOG.md` и статусы строк M2, M3, A4, K4 в акте сверки.
- Закрытие спринта в `PROJECT_STATE.md` не писать — это решение владельца.
