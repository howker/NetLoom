# Sprint 46 — новая оболочка интерфейса и общий контекст оператора

Статус: planned после закрытого Sprint 45.
Основа: `f475fec`, `docs/sprint45-field-acceptance.md`, полевой `FRICTION_LOG.md`, ADR-074–ADR-076 и при необходимости ADR-077.
Справочный макет: `docs/design/netloom-sprint46-obolochka.png`. Макет задаёт направление информационной архитектуры, а не pixel-perfect контракт.

## Operator outcome

Оператор понимает, где он находится, какой SNMP-профиль активен и что делает система, — без верхней панели из десятков элементов, отдельных окон редакторов и скрытых зависимостей между вкладками.

Sprint 46 — фундамент оболочки. Подробный progress monitoring, объяснимое discovery и масштабная карта выполняются затем как Sprints 47, 48 и 49 внутри этой оболочки. Буквенные срезы 46A–46E отменены.

## Почему оболочка делается первой

Полевой Sprint 45 показал несколько разных симптомов одного класса: зависимость мониторинга от выбора профиля в другом разделе, слабая видимость состояния работы, большое количество переключений между поверхностями и отдельными окнами, а также повторяющийся startup viewport friction. Если исправлять каждую проблему внутри старой верхней панели и существующих editor windows, последующий shell rework потребует повторной переделки.

Sprint 46 поэтому перекомпоновывает уже работающие возможности, не меняя их доменную семантику. Sprints 47–49 затем заполняют готовую оболочку.

## Структура оболочки

```text
┌──┬──────────────┬───────────────────────────────┬──────────────────┐
│  │              │ Объект › Здание › Помещение │ [иконка] SW-CORE │
│Р │ Боковая      │───────────────────────────────│ Обзор Интерфейсы │
│е │ панель       │                               │ Связи  Основания │
│й │              │          КАРТА                │                  │
│л │ для «Карты»: │    [кластер масштаба]         │   Инспектор      │
│  │ дерево       │                               │   выбранного     │
│  │ площадок и   │                               │   элемента       │
│  │ фильтры      │                               │                  │
├──┴──────────────┴───────────────────────────────┴──────────────────┤
│ лента событий: 14:32 цикл завершён · 14:31 SW-B1 ошибка SNMP · … │
└───────────────────────────────────────────────────────────────────┘

верхняя строка: NetLoom · Профиль SNMP: АГПЗ-v2c · состояние мониторинга
```

### Полоса разделов

Левая часть имеет два уровня, как activity rail + context sidebar:

- Карта;
- Оборудование;
- Предупреждения, включая счётчик;
- Обнаружение;
- Поиск MAC/IP;
- Настройки.

Внизу rail находится постоянная компактная сводка мониторинга: состояние, количество устройств под опросом и время последнего цикла. В Sprint 46 она использует уже доступные данные; полноценный progress `N / всего`, текущее устройство и ошибки добавляет Sprint 47.

### Контекстная боковая панель

Содержимое зависит от активного раздела. Для Карты это дерево Locations и фильтры слоёв.

Существующие editor windows не переписываются с нуля. `ManualTopologyWindow` и `LocationTopologyWindow` механически извлекаются в переиспользуемые `UserControl`/панели и размещаются в оболочке. Поведение, принятое в Sprints 37–38, сохраняется.

### Верхняя строка

Активный SNMP-профиль виден из любого раздела. Состояние мониторинга не прячется в expander или отдельной вкладке.

### Хлебные крошки

Breadcrumbs строятся из принятой в Sprint 38 иерархии Locations и показывают текущий физический контекст.

### Инспектор

Существующая диагностика Sprint 35 становится единым правым инспектором выбранной сущности. Инспектор получает тип и стабильный идентификатор сущности: устройство, интерфейс, связь или Location.

Для устройства целевое представление содержит вкладки:

- Обзор;
- Интерфейсы;
- Связи;
- Основания.

«Основания» остаются первоклассной частью продукта и не прячутся в tooltip.

### Нижняя лента событий

Последние события показываются одной компактной строкой/лентой. Переход по событию ведёт в раздел Предупреждения с сохранением контекста выбранной сущности, где это возможно.

## Что куда переезжает

| Сейчас | Sprint 46 |
| --- | --- |
| Верхняя панель из множества элементов | удаляется как основной navigation surface |
| Масштаб, Show all, lock/navigation controls | компактный плавающий кластер на карте |
| Monitoring expander | сводка внизу rail + соответствующий раздел |
| Выбор SNMP-профиля внутри Discovery | постоянный общий контекст |
| Discovery | отдельный раздел rail |
| Поиск MAC/IP | отдельный раздел rail |
| Настройки карты/справка | раздел Настройки и локальные map controls |
| `ManualTopologyWindow` | режим/панель внутри оболочки |
| `LocationTopologyWindow` | режим/панель внутри оболочки |

Новых top-level editor windows Sprint 46 не создаёт.

## Общий контекст SNMP-профиля

В Sprint 46 входит устранение скрытой зависимости между discovery и monitoring:

- выбранный профиль общий для обнаружения и мониторинга;
- последний выбранный профиль восстанавливается после restart;
- отсутствие профиля блокирует действие понятным сообщением до запуска Engine;
- секрет профиля не отображается в UI, состоянии или журналах;
- Ошибка профиля показывается там, где из-за неё ухудшились данные, даже если сам профиль редактируется в Настройках.

## Единая семантика статусов

- один набор design/status tokens для rail, карточек, discovery и monitoring;
- левая полоса карточки меняется вместе с доказанным состоянием;
- неизвестное состояние остаётся нейтральным;
- Статус всегда кодируется цветом и ещё одним независимым признаком: текстом, значком, формой или подписью.

Это закрывает полевой дефект Sprint 45, где цветная полоса воспринималась как состояние, но визуально не отражала ожидаемое изменение.

## Светлая и тёмная тема

Foundation уже содержит `Light`/`Dark` palettes. Sprint 46 добавляет пользовательский переключатель Светлая / Тёмная тема и сохраняет выбор между запусками. Новые поверхности используют только общие design tokens.

## Принципы взаимодействия

- одиночный клик выбирает сущность и обновляет инспектор, не меняя pan/zoom карты;
- двойной клик или `Enter` открывает полный вид выбранной сущности;
- `Esc` возвращает ровно предыдущий контекст карты;
- важная информация, доступная по hover, доступна и через selection; hover только ускоряет просмотр;
- настройки отделены от ежедневной работы;
- SNMP profiles, polling defaults и discovery ranges живут в Настройках, но ошибка профиля показывается у пострадавшего рабочего результата;
- Первая вкладка «Обзор» отвечает «что это и всё ли в порядке», а не превращается в конструктор дашбордов.

## Viewport и restart

Класс startup viewport friction проявился в Sprint 38, повторно в Sprint 43 и снова в полевой приёмке Sprint 45. Sprint 46 не переносит этот дефект в новый shell.

После restart оператор должен получить полезный вид настроенной топологии без обязательного `Show all`. Сохранённый viewport применяется только если он по-прежнему даёт осмысленный вид; shell layout/resizing не должен поздно вытолкнуть топологию за пределы рабочей области.

## Ограничения Sprint 46

- перекомпоновка существующего без новых данных и SQLite migrations;
- без изменения LLDP/CDP/STP/FDB/ARP semantics;
- без новой probabilistic confidence model;
- без нового общего graph-layout engine;
- без новых top-level windows;
- только shared design tokens, без локальных кистей/spacing/font-size literals;
- сохранение принятых PNG/CSV export и lookup flows;
- ручные позиции карты имеют приоритет;
- Исправление startup viewport входит в shell acceptance, а не откладывается дальше.

## Acceptance Sprint 46

Sprint 46 считается принятым, когда:

- на полевой базе из 55 устройств после restart сразу видны активный профиль и состояние мониторинга;
- мониторинг запускается без посещения Discovery;
- верхняя панель инструментов больше не является основной оболочкой;
- отдельные рабочие окна `ManualTopologyWindow` и `LocationTopologyWindow` больше не требуются в обычном flow;
- выбор устройства, интерфейса, связи или Location открывает единый инспектор и не сдвигает карту;
- тема переключается Light/Dark и переживает restart;
- статус нигде не зависит только от цвета;
- startup viewport после restart остаётся полезным;
- вопрос «что сломалось, где физически, через какой порт» решается не более чем за три действия;
- PNG и CSV export проходят без регрессии;
- shell проходит проверку на реальном Windows Server 2012 R2 в состоянии площадки.

## Sprint 47 — видимый прогресс мониторинга

Sprint 47 заполняет сводку в rail и рабочую поверхность monitoring.

Показываются состояния:

- остановлен;
- запускается;
- выполняется цикл;
- останавливается;
- Ошибка.

Показывается progress:

- `N / всего`;
- progress bar;
- текущее устройство и адрес;
- успешно;
- ошибок;
- осталось;
- Время начала и завершения цикла.

События цикла попадают в нижнюю ленту. Действия зависят от состояния:

- «Опросить выбранное устройство» при остановленном monitoring;
- «Запустить цикл сейчас» при работающем scheduler.

Operator outcome Sprint 47: по одному взгляду понятно, идёт ли опрос, какое устройство обрабатывается, сколько сделано и осталось, были ли ошибки и закончился ли цикл.

## Sprint 48 — обнаружение с объяснимым результатом

Раздел Discovery использует принятую форму диапазона:

- Начальный IP;
- Конечный IP;
- Маска.

Текущий адрес должен быть заметен. Найденные и изменившиеся устройства поднимаются вверх, а не теряются в длинном потоке.

Каждый результат относится к одной из шести объяснимых категорий:

```text
готово        ICMP + SNMP + идентичность + данные топологии
частично      отвечает, но SNMP или LLDP неполные
уже известно  устройство было в базе, изменений нет
изменилось    известное устройство сменило идентичность или интерфейсы —
              показать, что именно
исключено     попало под правило исключения профиля — показать какое
              (access_profile_exclusions)
ошибка        таймаут, аутентификация, протокол
```

Пример причины:

```text
SNMP: ошибка аутентификации · профиль АГПЗ-v2c · 14:32 · проверить снова
```

Итог discovery показывает:

- проверено;
- найдено;
- ошибок;
- Длительность.

До сохранения профиля доступна проверка профиля с разбивкой по доступности и MIB:

```text
✓ доступность             14 мс
✓ sysName, sysObjectID
✓ IF-MIB                  52 интерфейса
✓ LLDP-MIB                18 соседей
✓ BRIDGE-MIB
⚠ Q-BRIDGE-MIB            частично
```

Проверка особенно важна для смешанного парка площадки, включая Moxa, MikroTik и неуправляемые устройства. Секрет профиля при этом не раскрывается.

Operator outcome Sprint 48: после discovery понятно, что найдено полностью, что частично и почему, что уже было известно, что изменилось и какое правило/ошибка ограничило результат.

## Sprint 49 — читаемая карта большой площадки

Главный принцип Sprint 49 — не строить новый универсальный layout engine, а показывать меньше и менять детализацию по контексту.

### Focus-neighborhood

По умолчанию показывается выбранный узел и непосредственные соседи. Доступны явные действия:

- Раскрыть вверх;
- Раскрыть вниз;
- Вся площадка.

### Semantic zoom

Уровень детализации зависит от масштаба:

- издалека — Locations;
- средний масштаб — устройства;
- Вблизи — порты и подписи связей.

Это закрывает класс прежнего friction с нечитаемыми подписями и уменьшает плотность информации на 55+ устройствах.

### Качество данных

Над картой показывается строка вида:

```text
Топология неполная: N
```

С раскрытием причин. Полевой пример Sprint 45 включает как минимум одну связь уровня Observed и один synthetic interface; shell не должен превращать такие данные в визуально «полную» топологию.

### Новые узлы и ручная раскладка

Автоматическое предотвращение перекрытий применяется только к новым узлам, появившимся после discovery. Существующие ручные позиции неприкосновенны.

### Навигация

- `Ctrl+K` — поиск;
- `F` — фокус на выбранном;
- `Esc` — возврат к карте в прежнем масштабе;
- `Alt+←` — предыдущий вид;
- Удержание `Space` — временное панорамирование, как в CAD.

### Работа со связями

Hover связи подсвечивает ровно два её порта, остальные связи приглушаются. Та же существенная информация доступна и через selection.

`Shift+click` по двум устройствам показывает кратчайший известный физический путь между ними на существующем графе.

Double-click по Location вписывает в экран её поддерево.

Параллельные физические связи между одной парой устройств показываются раздельно, а не сливаются в одну линию. Модель `LinkKey` уже поддерживает параллельные связи; Sprint 49 обязан проверить текущую визуализацию и исправить только presentation layer, если они сейчас сливаются.

Operator outcome Sprint 49: на 55 и более устройствах карта читается без массовых перекрытий, оператор понимает область фокуса и видит, где данные неполны.

## Не входит в Sprint 46

Подавление зависимых предупреждений, логические tags, Visio export, MAC history, maintenance windows, полноэкранная операторская, расширенная диагностика устройства и изменения retention остаются backlog candidates и не расширяют shell Sprint.
